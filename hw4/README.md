# Factory vs AbstractFactory: вибір

## Вступ

У світі програмування патерни проектування допомагають створювати гнучкі та підтримувані програми. Два популярні патерни для створення об'єктів — **Factory Method** та **Abstract Factory**. Хоча вони обидва вирішують проблему інкапсуляції створення об'єктів, їх використання залежить від конкретних потреб проєкту.

## Різниця між Factory Method та Abstract Factory

### Factory Method

**Factory Method** — це патерн, який визначає інтерфейс для створення об'єкта, але дозволяє підкласам змінювати тип створюваного об'єкта. Основна ідея полягає у відділенні логіки створення об'єктів від їх використання.

**Особливості:**

- Створює один продукт.
- Дозволяє підкласам визначати конкретний тип створюваного об'єкта.
- Використовується, коли програма повинна делегувати створення об'єкта підкласам.

**Приклад використання:**

- Створення різних видів документів у текстовому редакторі (Word, PDF, HTML).
- Створення кнопок для різних операційних систем (WindowsButton, MacButton).

### Abstract Factory

**Abstract Factory** — це патерн, який надає інтерфейс для створення сімейств взаємопов'язаних або залежних об'єктів без вказівки їх конкретних класів. Він дозволяє створювати групи об'єктів, які працюють разом.

**Особливості:**

- Створює сімейство продуктів.
- Гарантує сумісність між продуктами одного сімейства.
- Використовується, коли потрібно створювати взаємопов'язані об'єкти разом.

**Приклад використання:**

- Створення UI для різних платформ (кнопка, текстове поле та меню для Windows або Mac).
- Генерація об'єктів для різних тем оформлення (світла тема, темна тема).

## Порівняння переваг і недоліків

| Патерн         | Переваги                                 | Недоліки |
| -------------- | ---------------------------------------- | -------- |
| Factory Method | - Гнучкість у створенні окремих об'єктів |          |

- Легко розширювати нові продукти | - Може створювати велику кількість підкласів
- Складність, якщо продуктів багато |
  | Abstract Factory | - Створює сумісні сімейства об'єктів
- Зменшує залежності між класами | - Складніша структура
- Додавання нових продуктів потребує змін у всіх фабриках |

## Висновок

- **Factory Method** краще використовувати, коли потрібно створювати один об'єкт і є ймовірність додавання нових типів продуктів.
- **Abstract Factory** підходить, коли потрібно створювати групи сумісних об'єктів, що працюють разом.

Вибір між ними залежить від потреб програми: окремий продукт чи ціле сімейство продуктів.
